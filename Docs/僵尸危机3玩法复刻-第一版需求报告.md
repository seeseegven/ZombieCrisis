**ZombieCrisis｜《僵尸危机3》玩法复刻需求报告**

版本：V0.2 · 单人单图 PvE 基线  
日期：2026年9月14日  
参考作品：Boxhead: 2Play Rooms（国内常称《僵尸危机3》）  
目标环境：Unreal Engine 5.8，Windows PC  
本次交付：需求文档；不包含编辑器操作或游戏实现。

**一、项目目标与证据边界**

第一版优先还原：单人、单张地图的 PvE，包含固定斜俯视战斗、普通僵尸与红色恶魔、十个武器／道具槽位、连杀倍率成长、房间地形和波次生存。先用手枪／UZI／霰弹枪跑通基础战斗与死亡重开，再补齐十种装备与58条成长。本地双人、联网和其他地图暂缓。新增机制等用户后续提出后再另行记录，不混入本版。

参考版本必须锁定为 2Play Rooms。发行方将它与 The Rooms、More Rooms、The Zombie Wars、The Nightmare 分开列出；不能把后续作品的怪物、武器、货币或基地系统当成本作规则。[发行方系列介绍](https://www.crazymonkeygames.com/series/Boxhead-Series.php)

**三、基本操作与战斗节奏**

| 操作 | 单人默认 | 合作／对战 P1 | 合作／对战 P2 |
|---|---|---|---|
| 移动 | 方向键 | 方向键 | W／A／S／D |
| 开火／使用当前道具 | Space | / | Space |
| 切换武器 | 数字 1～9、0 | , 上一件；. 下一件 | Q 上一件；E 下一件 |

发行方指南分别列出了单人和双人按键；游戏介绍页补充了 P 暂停。第一版只实现单人列，允许重绑定；双人列仅为原版资料存档。[发行方操作指南](https://www.crazymonkeygames.com/guide/Boxhead-2Play-Rooms/)、[发行方游戏页](https://www.crazymonkeygames.com/Boxhead-2Play-Rooms.html)

首版操作约定 D：

- 采用八方向移动与朝向；停止移动时保留最后朝向，沿当前朝向开火。八方向和转向细节须在原版实测时对照。
- 同时支持移动与射击，不加入瞄准镜、翻滚或冲刺资源。
- 斜向移动速度归一化；人物移动不受屏幕分辨率影响。
- 切换所有已解锁武器，不限制为“只携带两把主武器”。
- 开火是否连续、投掷是否蓄力、道具布置是否重复触发，按武器分别定义。
- 暂停同时冻结敌人、弹道、爆炸计时、连杀衰减与波次推进。

生存循环：开始单人游戏 → 固定地图、初始装备入场 → 走位射击与布置道具 → 击杀提高倍率并触发成长 → 消灭本波所有应生成敌人 → 下一波 → 玩家死亡后结算 → 重新开始。

不预设最终通关波数。波间等待时长、是否按键推进、是否有自动回血或补弹，列入实测项目；不能直接沿用前稿的8秒休息与固定百分比回复。

**四、“成长等级”实际上由三个不同概念组成**

| 名称 | 含义 | 是否会下降 | 用途 |
|---|---|---|---|
| 波次 Wave | 当前第几轮敌人 | 正常对局中不倒退 | 刷怪与难度推进 |
| 连杀倍率 Multiplier／Combo | 当前连续击杀奖励进度 | 会随时间下降 | 得分与成长门槛 |
| 已解锁成长集合 | 已经获得的武器和升级条目 | 倍率下降不撤销，按社区记录拟采用 | 确定当前可用装备和属性 |

发行方明确说明：每次击杀让倍率增加1，倍率随时间下降，而且较高倍率衰减更快；达到指定倍率可以获得新武器或强化。[成长规则官方说明](https://www.crazymonkeygames.com/guide/Boxhead-2Play-Rooms/)

早期玩家记录进一步说明，倍率下降不会移除已获得升级；普通开局只有无限弹药的手枪。该部分按 B 采用，正式还原前对照原版。[2010年玩家记录](https://onewdesign.wordpress.com/2010/10/01/5-games-on-kongregate-you-should-play-or-advertisement/)

成长功能要求 D：

- 每个升级条目有唯一编号；首次达到门槛时触发一次。
- 一次爆炸造成多次击杀时，要检查所有被跨过的门槛，不漏掉中间奖励。
- 倍率跌落再升回门槛时，不重复累乘同一升级，也不重复赠送解锁奖励。
- 新开一局清空成长；本版玩家死亡即结束对局，不实现合作复活。
- 得分、当前倍率、历史最高倍率分别保存，不用累计击杀数代替当前倍率。
- 截图中125是可见升级终点，不是玩家125级，也不是第125波。
- 999可列为社区参考的倍率上限，暂不宣称已由官方证实；上限必须可配置。

倍率衰减公式仍为 U：不能用“固定每秒下降1”代替官方所述的高倍率加速衰减。可先设置可替换曲线，但数值验收必须基于同版本实测。

统一武器要求 D：

- 弹药按武器独立记录；不引入一套未经证实的“弹匣＋备用弹药＋R换弹”。
- 弹丸、射速、伤害、范围、射程、击退和弹药分别可调。
- 布置行为必须检查占用位置；放置失败不扣库存，不把两个实体道具放进同一格。
- 一次范围伤害对同一目标只结算一次；后续集束子爆炸可作为独立伤害事件。
- 连锁爆炸不得对已销毁爆炸物重复触发；同一死亡只计一次击杀与奖励。
- 墙体是否阻挡爆炸、爆炸是否距离衰减均为 U；不能默认加入现代射击游戏规则。
- 弹药耗尽自动切回手枪有玩家资料支持，但需测试“按住使用键”时的连续触发行为，避免复刻时改变原作节奏。

**八、两种敌人的行为需求**

普通僵尸移动较慢，以近战和数量形成压力；恶魔更耐打并能远程发射能量球，持续快速命中能阻止它发射。发行方还明确提醒玩家注意爆炸自伤。[敌人及爆炸说明](https://www.crazymonkeygames.com/guide/Boxhead-2Play-Rooms/)

| 敌人 | 必须呈现的行为 | 不应擅自增加的能力 |
|---|---|---|
| 普通僵尸 | 追踪玩家、近身攻击、形成拥堵与包围；被攻击时有清晰反馈 | 奔跑变种、跳跃、自爆、喷毒、召唤 |
| 红色恶魔 | 追踪／选择射击机会、发射可见火球、较强生存能力、受持续命中压制 | 终局专属阶段、瞬移、冲撞、全屏技能 |

需求约定 D：

- 红色恶魔可作为同一波中的敌人出现，不做成“全场只刷一只且击杀即通关”的最终Boss。
- 追击遇到不可通行墙体时必须处理绕路；假墙造成封路时的停留、攻击或绕行逻辑以原版对照结果决定。
- 敌人不得因为路径失败永久阻止波次结束；调试记录需区分寻路失败与合法堵路。
- 恶魔的压制必须可观察：连续命中时不能继续按完全相同节奏发射火球。
- 精确击退幅度、硬直和恢复射击延迟保持可配置。
- 玩家、敌人、火球、墙体、桶与地雷分别建立碰撞和伤害关系，不能用“所有物体互相伤害”简单替代。

**九、波次、难度与僵尸数量**

本版按持续波次生存组织，不设剧情终点；原版内部是否存在最终波次或数值上限尚未核实。社区描述支持波次逐渐增加敌人压力，但不提供足够可信的逐波数量表。

| 波次配置字段 | 含义 | 要求 |
|---|---|---|
| WaveIndex | 波次编号 | 与倍率分开显示 |
| ZombieCount | 本波普通僵尸总数 | U：需采样原版 |
| DevilCount | 本波恶魔总数 | U：首次出现波次也需核实 |
| SpawnSchedule | 生成顺序、入口、生成间隔 | 不默认一次生成整波 |
| AliveLimit | 场上存活上限 | 若为性能保护新增，必须标D，不得改变应生成总数 |
| EnemyOverrides | 本波敌人属性变化 | 只有测到血量／速度变化后才确认曲线 |
| StartLoadout | 从高波次或高难度开始时的装备 | 单独测试，不能用普通开局推定 |
| EndCondition | 波次完成条件 | 待生成数为0且存活敌人为0 |

采样要求 D：固定同一个非修改版、同一地图和同一难度，连续记录前20波普通僵尸数量、恶魔数量、生成时序，再抽查后续高波次。若无法确认公式，先使用实测波次表，不外推成“每波固定加5只”。

难度需要配置化。已有社区记录显示存在 Nightmare 等设置，但各档是否改变起始波次、装备、倍率或敌人属性仍需逐项测量，不能只设计成简单的血量乘数。[原版玩家设置记录](https://www.kongregate.com/en/games/seancooper/boxhead-2play-rooms)

**十、补给、地形与阵地战**

早期玩家记录描述地图上有红色补给箱，拾取后恢复弹药或生命，并在原位置再次出现；合作中还有友伤、碰撞与恶魔开关。其详细计时与边界规则未经过本次实测。[早期玩法记录](https://onewdesign.wordpress.com/2010/10/01/5-games-on-kongregate-you-should-play-or-advertisement/)

首版需求 D：

- 设置明确的地图补给点，使玩家需要离开安全位置补给。
- 生命与弹药显示真实当前量，拾取时给出反馈；满量时是否仍消耗补给由原版测试决定。
- 保留敌人掉落补给的扩展配置，但掉落概率、必掉敌人、存在时长目前为U。
- 不自动加入每波恢复10%生命、随机医疗包概率或缺弹保底机制。
- 场景固定墙、玩家假墙、爆炸桶必须区分耐久与受击规则。
- 假墙、桶、地雷和炸药包的摆放上限、布局对寻路的影响，需要成为核心玩法测试，而不是只测试模型是否生成。
- 本版核实并实现爆炸自伤；合作友伤设置暂缓。

首版地图验收：至少包含可绕行空间、一个可组织火力的窄口、多个出怪入口和可到达补给点；地图并非必须公平开放，原版式封路和阵地战应能成立。

**十一、双人合作与对战（原版资料存档，本版不实现）**

三种模式的存在由开发者说明确认；具体复活和对战初始装备可参考早期玩家实录：合作双方都死亡时结束，有存活队友时可等待复活；对战不刷僵尸，开局开放装备与强化。这些细节为B，复活计时、复活后成长与对战胜局数为U。[开发者模式说明](https://www.kongregate.com/en/games/seancooper/boxhead-2play-rooms)、[早期双人记录](https://onewdesign.wordpress.com/2010/10/01/5-games-on-kongregate-you-should-play-or-advertisement/)

后续多人版本参考约定 D；以下全部不参与本版交付与验收：

- 同机双人使用共享摄像机，不默认分屏或网络联机。
- 两名玩家的生命、弹药、所选武器、死亡状态独立。
- 击杀归属、倍率是否共享、队友击杀是否同时触发成长均列为U，需在同一局对照测试。
- 合作队友死亡时显示复活等待状态；不引入原版未经证实的倒地救援交互。
- 对战独立配置伤害、局数与计分；不得直接套用生存模式的数值。
- 友伤关闭时的爆炸自伤、火球伤害、敌我碰撞边界需要分别测试。

**十二、界面、声音与表现**

下列为本项目界面需求 D，依据原作功能与用户截图安排：

| 界面 | 必须提供的信息或操作 |
|---|---|
| 主菜单 | 开始单人游戏、设置、操作说明 |
| 对局设置 | 固定一张地图、一个默认角色外观和标准难度；无地图／模式选择流程 |
| 战斗HUD | 生命、当前武器、弹药、波次、得分、当前倍率 |
| 成长提示 | 达到门槛后显示武器解锁或升级名称 |
| 升级列表 | 固定门槛、升级名称、已获得与未获得状态；新武器用明显颜色区分 |
| 暂停 | 继续、操作说明、升级表、重新开始、退出 |
| 结算 | 本局得分、最高倍率、到达波次、击杀数量、再来一局 |

画面先用自制或引擎基础资源实现方块风格占位，重点保证视角、人物轮廓、敌我区分、弹道、爆炸和地形可读。只需一个默认玩家外观，不加入角色选择或职业属性。红色恶魔、补给和爆炸桶应有不同轮廓，避免只靠红色区分。

音效至少区分：开火、空弹、切换、道具放置、爆炸、受伤、死亡、补给、升级和新波次。第一版不默认加入飘字伤害，数值显示放在调试模式中，避免影响原版风格。
